# @ninjavault/cdn 100.42.1

Date: 2026-09-28
Type: Major

## Changes
- First public release on npm.
- Same version and feature set as `NinjaVault.Cdn` 100.42.1 on NuGet and `ninjavault-cdn` 100.42.1 on PyPI:
  every NinjaVault SDK uses the same three-part version number.
- `NinjaVaultCdnClient` covers access validation (`getAccessContext`), bucket discovery (`listBuckets`),
  multipart upload (`upload`), file listing/search (`listFiles`), metadata (`getMetadata`), usage summary
  (`getSummary`), streamed authenticated download (`download`), soft delete (`delete`), public URL building
  (`buildPublicUrl`) and single/batch presigned URLs (`createPresignedUrl`, `createPresignedUrls`).
- Configuration from options or the `NINJAVAULT_CDN_BASE_URL`, `NINJAVAULT_CDN_API_KEY` and
  `NINJAVAULT_CDN_PUBLIC_BASE_URL` environment variables. A `baseUrl` with a path prefix works.
- Error envelopes map to `CdnApiError` (HTTP status, CDN error code, description, trace id as
  `correlationId`, validation `details`, `retryAfterMs` from `Retry-After`). `CdnTimeoutError` for the SDK
  timeout; caller aborts reject with the standard `AbortError`.
- `hooks` (`onRequest`, `onResponse`, `onError`) for logging and correlation, with the API key redacted.
- Zero runtime dependencies. Built on `fetch`, `FormData`, `Blob` and web streams: Node 18+, Bun, Deno and
  edge runtimes. Dual ESM + CommonJS with TypeScript types.
- Follows the server contract where the .NET client differs: tenant ids are strings (numeric id or GUID),
  `viewUrl` is exposed on uploads and file objects, and `sortBy` sends the server's `CreatedAtUTC` name.

## Why
- Let Node.js and TypeScript teams integrate with the NinjaVault CDN Server by installing one package instead
  of hand-rolling API-key headers, multipart fields, object-key encoding and the JSON envelope.

## Breaking Changes
- None (first public release).
